# Release notes

Every release tag must have a hand-written Markdown file in this directory
named after the tag, for example `v0.7.0.md`. The release workflow fails closed
when that file is missing or empty and publishes it verbatim as the GitHub
release description.

Write for operators, not for the commit log: lead with behavior and operational
impact, call out upgrade or migration requirements, and link the relevant pull
requests and longer guides where they help.
