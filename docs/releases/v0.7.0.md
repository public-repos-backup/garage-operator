v0.7.0 introduces drain-safe, DaemonSet-backed node-local storage while keeping
existing PVC, SMB, Ceph, external, and gateway deployments supported. Node-local
pools are experimental and opt-in; upgrading an existing cluster does not move
or rewrite its storage.

## Highlights

### Node-local storage pools

`GarageCluster` v1beta2 now supports `spec.storage.nodeLocalPools`. Each pool
selects Kubernetes Nodes and runs one Garage identity per selected Node, with
metadata and block data on explicitly provisioned HostPaths. The operator
serializes activation, config and image rollouts, selector changes, drains, and
deletion so two Garage processes cannot mount the same `node_key` concurrently.

Membership changes are add-before-remove and health gated. Before retiring a
positive-capacity identity, the operator verifies its replacement capacity,
Garage layout convergence, repair queues, block health, and a quiet resync
window. Lost-node recovery remains an explicit, fail-closed procedure.

See the [node-local pool guide](https://github.com/rajsinghtech/garage-operator/blob/v0.7.0/docs/node-local-pools.md)
and [migration guide](https://github.com/rajsinghtech/garage-operator/blob/v0.7.0/MIGRATION.md)
before enabling a pool. Thanks to [@florissmit10](https://github.com/florissmit10)
for the original DaemonSet contribution, completed and hardened in
[#297](https://github.com/rajsinghtech/garage-operator/pull/297).

### Better failure-domain placement

Storage nodes can derive their Garage zone from a Kubernetes Node label with
`zoneFrom`, allowing one `GarageCluster` to represent multiple real failure
domains without splitting one site lifecycle into several cluster objects
([#302](https://github.com/rajsinghtech/garage-operator/pull/302)).

### Safer operations and clearer failures

- Graceful node cycling no longer depends on `updateTrackers` after Garage has
  collapsed layout history to one live version, preventing a permanent
  `Syncing` wedge ([#308](https://github.com/rajsinghtech/garage-operator/pull/308)).
- Layout rebuilds use one exact Garage Pod instead of routing substituted admin
  credentials through the cluster Service
  ([#306](https://github.com/rajsinghtech/garage-operator/pull/306)).
- Unsupported bucket lifecycle rules now fail visibly instead of being silently
  dropped, and the supported Garage version contract is documented
  ([#300](https://github.com/rajsinghtech/garage-operator/pull/300)).
- User-provided PVC labels and annotations are projected again
  ([#290](https://github.com/rajsinghtech/garage-operator/pull/290)).

## Upgrade notes

- Garage v2.0.0 or newer is required; v2.3.0 is the tested default.
- Existing clusters that do not declare `nodeLocalPools` need no storage
  migration. Do not convert a live LocalPath PVC into a HostPath by changing one
  manifest: add fresh pool identities and drain old nodes one at a time, or use
  the guide's explicit offline identity-preserving handoff.
- Pools require Kubernetes 1.27 or newer, a cluster-scoped operator install,
  enabled validating and conversion webhooks, and permission for HostPath in
  the workload namespace.
- Production HostPaths should use `hostPathType: Directory` and contain a
  `.garage-volume-id` marker on the mounted filesystem. The operator will not
  create the marker for you.
- Pool topology changes must be separate from retained runtime/config changes.
  Federated removals require every site to run literal `consistent` mode and
  explicitly acknowledge the peer-consistency assumption described in the
  migration guide.
- Garage environment variables owned by the operator are now reserved. Remove
  conflicting user overrides before upgrading; migration annotations exist for
  the documented legacy credential and config cases.

## Release integrity

Release images, Helm charts, and the generated install manifest are signed or
attested through GitHub's OIDC identity. Container images and charts also carry
provenance, and images carry an SPDX SBOM
([#299](https://github.com/rajsinghtech/garage-operator/pull/299)). Verification
commands are documented in the project README.
